# Admin Card Registration With OTP Implementation Plan

## Goal

Change card creation so Admin and Operator users can register a card after verifying the owner's phone number with OTP.

New workflow:

```text
Admin or Operator enters phone number
System sends OTP to that phone number
Admin or Operator enters OTP
If OTP is valid, show card creation form
Admin or Operator enters owner name
System auto-generates card number
System creates card
```

## Important Format Rule

Card number should be generated by the system.

Requested format:

```text
crd + ddMMyyyy + 4-digit daily sequence
```

Examples:

```text
crd080820260001
crd080820260002
crd090820260001
```

Note: this is `crd` plus 12 digits, so the full card number is 15 characters. The numeric part is 12 digits.

## Phase 5: Card Number Generator

Create:

```text
YbsSmartCardSystem.Domain/Features/Card/CardNumberGenerator.cs
```

or keep it private inside `CardService` if small.

Generation rule:

```text
prefix = "crd"
datePart = local date as ddMMyyyy
sequence = next number for that date, padded to 4 digits
cardNumber = prefix + datePart + sequence
```

Example:

```text
crd080820260001
```

Query existing cards where `CardNum` starts with:

```text
crd + ddMMyyyy
```

Find the highest last 4 digits, then add 1.

Important concurrency rule:

- Add a unique index on `Tbl_Card.CardNum`.
- Generate and save inside a transaction.
- If duplicate occurs due to concurrent requests, retry generation a small number of times.

Use Myanmar/local server date only if that is the business requirement. Otherwise define a single application timezone.

## Phase 11: Validation And Security

OTP rules:

- 6 digits
- Expires after 3 to 5 minutes
- Max 5 attempts
- Do not reveal whether a phone number belongs to an existing user/card unless business requires it
- Rate-limit OTP sending per phone number if possible
- Store OTP hash, not plain OTP

Card number rules:

- Server generated only
- Unique
- Daily sequence resets every local date
- Last 4 digits support 0001 to 9999 per day
- If more than 9999 cards are created in one day, return a clear business error
